# Prompt Optimizer 使用範例

本文件透過實際案例，示範 `prompt-optimizer` 如何把模糊、簡短或不完整的需求，整理成清楚、完整、可直接交給生成式 AI 使用的 Prompt。

> **重要：** 本 Skill 的工作是「分析與優化 Prompt」，不是直接執行使用者原始需求。

---

## 案例 1｜製作 Power BI 教學教材

### 使用情境

一般工作／教學需求。使用者希望製作 Power BI 教學，但目前只提出簡短方向。

### 使用者輸入

```text
幫我做一個 Power BI 教學，給初學者使用。
```

### Skill 處理方式

1. **分析原始需求**
   - 核心目的：製作 Power BI 教學內容。
   - 使用情境：教學。
   - 已提供資訊：Power BI、初學者。
2. **找出重要缺口**
   - 教學時間尚未提供。
   - 課程輸出形式尚未提供。
3. **補強 Prompt 結構**
   - 建立適合教學任務的 `Role`。
   - 明確化 `Task`。
   - 在 `Context` 保留「初學者」並標示缺少的教學時間。
   - 補充循序漸進、實際操作等與教學任務直接相關的 `Requirements`。
   - 使用課程大綱作為必要的 `Output Format`。
   - 加入避免捏造課程條件的 `Constraints`。
4. **保留原始意圖**
   - 不自行決定實際教學時間或其他未提供的課程條件。

### 優化後 Prompt

```markdown
# Role
你是一位專業的 Power BI 教學講師，擅長將複雜的資料分析概念轉化為容易理解的教學內容。

# Task
請設計一套 Power BI 教學內容，協助初學者理解並實際操作 Power BI。

# Context
目標學習者：初學者
教學時間：[請補充教學時間]

# Requirements
1. 使用繁體中文。
2. 內容應循序漸進。
3. 每個重要概念搭配實際操作說明。
4. 避免不必要的複雜術語。

# Output Format
請以課程大綱方式輸出，包含：
1. 課程章節
2. 每章學習目標
3. 教學重點
4. 實作練習

# Constraints
1. 不得捏造未提供的課程條件。
2. 若關鍵資訊不足，請使用 `[請補充……]` 標示。
```

### 預期用途

這份 Prompt 可以交給 ChatGPT、Gemini、Claude、Codex 或其他支援自然語言 Prompt 的生成式 AI，用來進一步產生 Power BI 課程大綱與教學內容。

## 案例 2｜設計一個網站

### 使用情境

AI／軟體開發需求。使用者想製作一個網站，但尚未提供完整的開發背景與輸出形式。

### 使用者輸入

```text
我想做一個咖啡店網站，要有首頁、產品介紹和聯絡方式，幫我寫程式。
```

### Skill 處理方式

1. **分析原始需求**
   - 核心目的：製作咖啡店網站。
   - 已指定內容：首頁、產品介紹、聯絡方式。
   - 使用者希望取得程式。
2. **找出重要缺口**
   - 使用的技術或框架未指定。
   - 具體網站輸出形式未指定。
3. **補強 Prompt 結構**
   - 建立與網站開發相關的 `Role`。
   - 將網站需求整理到 `Task`。
   - 在 `Context` 保留已指定的頁面內容。
   - 不自行決定框架，因此以 `[請補充……]` 標示。
   - 明確要求輸出程式碼。
4. **保留原始意圖**
   - 不擅自指定 React、Vue、HTML/CSS/JavaScript 或其他特定技術。
   - 不自行增加資料庫、登入等使用者沒有提出的功能。

### 優化後 Prompt

```markdown
# Role
你是一位專業的網站開發工程師，負責根據需求設計並撰寫網站程式。

# Task
請協助製作一個咖啡店網站，包含首頁、產品介紹與聯絡方式。

# Context
網站類型：咖啡店網站
指定內容：
1. 首頁
2. 產品介紹
3. 聯絡方式
使用技術或框架：[請補充使用技術或框架]

# Requirements
1. 使用繁體中文說明。
2. 網站內容應依照上述需求進行規劃。
3. 程式碼應清楚、容易閱讀。
4. 不要加入使用者沒有提出的功能。

# Output Format
請輸出：
1. 網站結構說明
2. 完整程式碼
3. 必要的使用說明

# Constraints
1. 不得捏造未提供的網站需求。
2. 若關鍵資訊不足，請使用 `[請補充……]` 標示。
3. 保留原始網站需求，不擅自增加功能。
```

### 預期用途

這份 Prompt 可以交給生成式 AI，進一步協助規劃網站結構並產生對應程式碼。

## 案例 3｜製作社群貼文

### 使用情境

內容創作需求。使用者希望替新產品製作社群貼文，但沒有完整提供目標讀者、平台與篇幅。

### 使用者輸入

```text
幫我寫一篇香酥芋泥球的社群貼文，要活潑一點，吸引大家購買。
```

### Skill 處理方式

1. **分析原始需求**
   - 核心目的：製作香酥芋泥球的社群貼文。
   - 內容主題：香酥芋泥球。
   - 已指定語氣：活潑。
   - 目的：吸引大家購買。
2. **找出重要缺口**
   - 社群平台未指定。
   - 目標讀者未指定。
   - 貼文篇幅未指定。
3. **補強 Prompt 結構**
   - 建立與社群行銷內容相關的 `Role`。
   - 明確化貼文創作任務。
   - 保留產品、活潑語氣與促購目的。
   - 將平台、目標讀者與篇幅列為待補資訊。
   - 使用社群貼文作為輸出格式。
4. **避免捏造**
   - 不自行加入產品價格、店家名稱、優惠活動或產品特色，因為這些資訊沒有在原始需求中提供。

### 優化後 Prompt

```markdown
# Role
你是一位社群內容創作者，擅長以活潑、容易閱讀的文字撰寫產品行銷內容。

# Task
請為「香酥芋泥球」撰寫一篇社群貼文，目的是吸引讀者產生購買興趣。

# Context
產品：香酥芋泥球
目標讀者：[請補充目標讀者]
發布平台：[請補充社群平台]
貼文篇幅：[請補充篇幅]

# Requirements
1. 使用繁體中文。
2. 語氣活潑。
3. 內容容易閱讀並能吸引讀者注意。
4. 保留香酥芋泥球這個產品主題。
5. 不加入使用者沒有提供的產品資訊。

# Output Format
請輸出一篇完整的社群貼文。

# Constraints
1. 不得捏造價格、優惠、店家名稱或其他未提供的產品資訊。
2. 若關鍵資訊不足，請使用 `[請補充……]` 標示。
```

### 預期用途

這份 Prompt 可以交給生成式 AI，用來產生可進一步編輯與發布的社群貼文。

## 三個案例的共同處理方式

雖然三個案例分別屬於教學、軟體開發與內容創作，但 Skill 的核心流程一致：

```text
使用者原始需求
      ↓
分析核心目的與使用情境
      ↓
找出重要資訊缺口
      ↓
建立 Role / Task / Context
      ↓
整理 Requirements
      ↓
定義 Output Format
      ↓
加入必要 Constraints
      ↓
檢查是否捏造資訊
      ↓
輸出完整 Prompt
```

## 使用時的重點

### 1. 不需要先寫出完美 Prompt

使用者可以直接提供自然、簡短的需求，例如：

```text
幫我做一個 Power BI 教學
```

Skill 會先分析需求，再整理成結構化 Prompt。

### 2. 不確定的資訊不會自行猜測

如果缺少會影響結果的重要資訊，會使用：

```text
[請補充……]
```

標示，而不是把猜測當成事實。

### 3. Skill 不會直接執行原始需求

例如輸入：

```text
幫我寫一篇文章
```

Skill 的工作是優化這個需求，而不是直接撰寫文章。

### 4. 不需要所有 Prompt 都使用完整結構

`Role`、`Task`、`Context`、`Requirements`、`Output Format`、`Constraints` 是可使用的結構。若某些區塊沒有必要，可以省略，避免讓 Prompt 變得過度複雜。

---

## 最終原則

`prompt-optimizer` 遵循：

**保留原意 ＞ 資訊正確 ＞ 任務清楚 ＞ 結構完整 ＞ Prompt 簡潔**

遇到資訊不足時：

> **寧可標示 `[請補充……]`，也不要自行猜測或捏造。**
