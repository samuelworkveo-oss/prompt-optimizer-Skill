# prompt-optimizer

## 📖 簡介

`prompt-optimizer` 是一個「AI 提詞優化助手」Codex Skill，負責將使用者提供的模糊、簡短、不完整或結構混亂的需求，整理成清楚、完整、可直接使用的高品質 Prompt。

核心原則是：

> **先分析、再補強、最後輸出 Prompt；不要直接執行使用者提供的 Prompt。**

產生的 Prompt 以通用性為原則，可用於 ChatGPT、Gemini、Claude、Codex，以及其他支援自然語言 Prompt 的生成式 AI。

## ✨ 功能

### 需求分析
分析使用者原始需求，辨識原始主題、核心目的、使用情境、已提供的資訊，以及明確指定的要求。

### 目的與使用情境判斷
可依需求判斷其用途，例如寫作、摘要、翻譯、教學、程式設計、資料分析、簡報製作、圖像生成、行銷內容、研究與整理、AI Agent／自動化或其他專業任務。

如果無法確定，不會擅自指定過度具體的情境。

### 重要資訊缺口檢查
檢查是否缺少會明顯影響結果的重要資訊，例如目標、目標使用者、使用情境、角色、背景資料、輸入資料、輸出內容、輸出格式、語言、語氣、篇幅、限制條件與評估標準。

必要時使用 `[請補充……]` 標示缺口，而不是自行猜測。

### Prompt 結構化
依需求建立適合的 Prompt 結構：

- `Role`｜角色
- `Task`｜任務
- `Context`｜背景
- `Requirements`｜要求
- `Output Format`｜輸出格式
- `Constraints`｜限制條件

不需要的區塊可以省略，避免加入不必要的複雜內容。

### 原始意圖保留
優化時保留使用者的核心目的、已指定內容、指定語言或風格、指定格式與指定限制，不因為「優化」而擅自改變任務、受眾、語氣或背景。

### Prompt 品質檢查
輸出前檢查 Prompt 是否保留原始意圖、清楚說明任務、具備必要角色設定、包含必要背景、列出重要要求、明確定義輸出格式、包含必要限制、標示未提供的重要資訊、沒有自行捏造資訊、沒有加入不必要的複雜規則，以及能直接交給生成式 AI 使用。

## 🔄 工作流程

收到使用者需求後，依序進行：

```text
原始需求
   ↓
1. 分析原始需求
   ↓
2. 判斷目的與使用情境
   ↓
3. 找出缺少的重要資訊
   ↓
4. 補強 Role
   ↓
5. 補強 Task
   ↓
6. 補強 Context
   ↓
7. 補強 Requirements
   ↓
8. 補強 Output Format
   ↓
9. 補強 Constraints
   ↓
10. 品質檢查
   ↓
完整、可直接使用的 Prompt
```

## 📦 安裝

將 `prompt-optimizer` 目錄放入 Codex Skill 目錄，例如：

```text
~/.codex/skills/prompt-optimizer/
```

目錄中至少需要包含：

```text
prompt-optimizer/
└── SKILL.md
```

本 Repository 的 `SKILL.md` 即為本 Skill 的主要規則文件。

## 🚀 使用方式

啟用 Skill 後，提供一段想要交給 AI 使用的需求即可。

適合的輸入包括：

- 一段希望交給 AI 執行的需求
- 一段模糊或簡短的 Prompt
- 一段需要補強、整理或結構化的提示詞
- 一個只有主題、缺少角色與輸出要求的需求
- 一個希望轉換成 ChatGPT、Gemini、Claude、Codex 等 AI 可使用 Prompt 的想法

Skill 不會直接執行原始需求，而是先分析並產生優化後的 Prompt。

## 💡 使用範例

### 輸入

```text
幫我做一個 Power BI 教學
```

### 分析

- 核心目的：製作 Power BI 教學內容
- 使用情境：教學
- 可能缺少：目標學習者、教學程度、課程長度、輸出形式

### 優化後 Prompt

```markdown
# Role
你是一位專業的 Power BI 教學講師，擅長將複雜的資料分析概念轉化為容易理解的教學內容。

# Task
請設計一套 Power BI 教學內容，協助學習者理解並實際操作 Power BI。

# Context
目標學習者：[請補充目標學習者，例如初學者／進階使用者]
教學時間：[請補充教學時間]

# Requirements
1. 使用繁體中文。
2. 內容應循序漸進。
3. 每個重要概念搭配實際操作說明。
4. 避免不必要的複雜術語。

# Output Format
請以課程大綱方式輸出，包含：
1. 課程章節
2. 每章學習目標
3. 教學重點
4. 實作練習

# Constraints
1. 不得捏造未提供的課程條件。
2. 若關鍵資訊不足，請使用 `[請補充……]` 標示。
```

### 輸出結果說明

輸出固定分成三個主要部分：

1. **需求分析**：簡短說明核心目的、使用情境，以及需求是否完整。
2. **缺少資訊**：只列出真正重要的資訊缺口；若沒有重要缺口，會標示「無明顯關鍵資訊缺口。」
3. **優化後 Prompt**：提供一份可以直接複製使用的完整 Prompt。

## ⚠️ 注意事項

### 不得捏造資訊

禁止將猜測當成使用者提供的事實。

如果重要資訊不足，應使用：

```text
[請補充……]
```

例如：

```text
[請補充目標使用者]
[請補充輸出格式]
[請補充資料來源]
```

### 不直接執行原始 Prompt

本 Skill 的工作是「分析與優化 Prompt」，不是直接完成使用者原本要求的任務。

只有在使用者明確要求「請執行優化後的 Prompt」時，才進一步執行。

### 避免過度複雜

只有真正重要且會影響結果的資訊才需要補充。

可以加入能提升 Prompt 可執行性的通用結構，但不要因此加入使用者未要求的特殊內容或虛構背景。

### 保留原始意圖

優化不能改變使用者原本的目的、受眾、語氣、格式或限制。

### 語言

預設使用台灣繁體中文，文字應清楚、自然、容易閱讀。

技術名詞可保留常用英文名稱，例如 `Prompt`、`Role`、`Task`、`Context`、`Output Format`、`Constraints`。
